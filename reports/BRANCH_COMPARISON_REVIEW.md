# BRANCH_COMPARISON_Q3_Q4_REPORT(1).md 审阅结论

## 可确认的部分

- 当前仓库的正式基线是 main/cad128f 的 24 架次 Q2 CSV。
- 当前 q3_solver.py 的 GeoTIFF 内联标签偏移确实错误：短标签数据被错误读取为 IFD 后连续区域。独立解析显示真实 DEM 尺寸为 1486×1309，而旧代码读到 27344×27344；修复后抽样地面高程恢复为非零值。
- 原报告关于“旧版 0 中继结果受 DEM 解析错误影响”的判断成立。
- Q4 旧版本确实需要避免跨组架次重复计数，并需要按中继任务核算中继资源。

## 不能确认或已过时的部分

- 当前仓库没有 feature/q3-q4-tasks 分支，也没有 54e3ecb 提交；报告中 feature 分支的 3/4 架次、136 个遮挡区间、3.7309 kWh、7746.3 s 和缺口数字无法由当前仓库复现，不能作为已验证事实。
- 报告把 main 的 0 中继结果作为当前结论已经过时。修复 DEM 后重新运行 q3_solver.py 得到：24 架次、1344 个采样点、23 个架次使用中继、1 个架次直连、0 个中断；直连损耗范围 69.79–128.24 dB，最小直连裕度 -6.24 dB。
- 修复后 Q4 输出的中继需求为：K2_A 大组8架/8组件、小组1架/1组件；K2_B/K2_C大组8架/8组件、小组1架/1组件；K3三组分别为8/8、1/1、1/1。当前代码还没有完成中继飞行/悬停能耗和能源组件的完整物理审计，因此这些需求不能扩展成报告中 feature 的缺口结论。

## 当前建议

以当前代码和可复现结果为准，先不要采用附件报告中的 feature 对照数字。论文中应明确 DEM 修复、Q3 重新运行、23 架次中继和 0 中断，并补做中继能源/周转审计后再定稿。
